# Agent Note: pmind 收敛为 Swift 原生 macOS 思维导图文档应用

Status: implemented

## Problem

用户要求推翻现有实现，以 Swift 重构为简化、轻量的 macOS 原生应用，仅保留核心思维导图功能。现有 Go API、React SPA、账号、数据库、管理后台和 Docker 部署围绕自托管网站构建，继续维护这些层会让本地编辑承担不需要的安装和运行成本。

本次交付目标是能够在 Mac 上编译、打开和编辑本地导图的完整应用，而不是原生窗口套网页。当前工作区是 Linux，未安装 Swift 和 Xcode，不能把这里的静态检查当作 macOS 编译或界面验收。

## Decision

### 产品范围

默认目标平台为 macOS 14+，同时支持 Apple Silicon 和 Intel。名称使用 pmind，界面以简体中文为主，采用系统字体、SF Symbols 和系统浅色/深色外观。

| 范围 | 内容 |
| --- | --- |
| 文档 | 新建、打开、保存、另存为、自动保存、最近使用和多文档窗口 |
| 编辑 | 中心主题、子主题、同级主题、改名、删除、复制粘贴子树、折叠/展开 |
| 结构 | 拖拽改变父级与同级顺序；拒绝把主题放进自己的后代；左右思维导图与向右逻辑图两种布局 |
| 浏览 | 触控板平移和缩放、适应窗口、保持缩放定位中心主题、搜索并定位 |
| 组织 | 与画布同步的大纲、主题纯文本备注、少量分支配色 |
| 历史 | 系统菜单与快捷键支持撤销/重做；空操作不产生历史 |
| 交换 | Markdown 导入/导出、PNG 和 PDF 导出 |

移除 Web 前后端、账号/权限、API、数据库、AI、在线分享、管理后台、云备份、上传服务、Docker 和网站发布流程。首版不包含多画布、XMind/OPML、自由主题、概要、边界、跨节点联系线、附件、公式、任务系统、大量主题模板或协同编辑。这些功能不保留空入口。

### 原生技术和目录

采用 Swift 6、SwiftUI 应用外壳和 AppKit 画布，不引入运行时第三方依赖。SwiftUI 承担工具栏、侧栏、搜索、备注和系统菜单；AppKit NSView/NSScrollView 承担画布绘制、文本编辑、命中检测、拖拽与触控板事件。所有编辑入口调用同一套文档命令。

使用零外部依赖的根目录 SwiftPM 工程；Xcode 可直接打开 Package.swift。MindMapCore 库与 PMindApp 可执行目标分开，Linux 仅构建内核，macOS 构建原生应用；`script/build_and_run.sh` 生成开发用 .app 并启动，避免手写 pbxproj 的额外维护。布局测量通过协议注入，实际应用使用 AppKit 的系统字体测量，不把 SwiftUI 视图作为布局数据源。

当前目录为 `App/`、`Sources/MindMapCore/`、`Tests/` 和 `docs/`。根目录保留许可证和必要的工程说明。开发和应用运行不再依赖 Node、Go 或后台进程；笔记校验工具是否继续使用 Node 与产品运行依赖分开处理。

### 文档与状态契约

采用版本化 `.pmind` JSON 文件，包含主题树、顺序、折叠状态、备注、分支配色和布局类型。每个节点拥有稳定 UUID；编码和解码须验证唯一标识、深度、节点数及格式版本。无法支持的较新格式必须拒绝覆盖保存。

原生 JSON 使用紧凑、键排序编码；8 MiB 上限同时用于读取原始文件和验证可再次保存的编码结果。读取旧的带缩进文件仍保留全部字段。深树中的缩进会成倍增加体积，因此不能让一个约 0.75 MB、7111 主题的合法文件在打开后因 pretty-print 超过限制而无法保存或改名。读取时多做一次编码，以保证后续保存遵循相同契约。

优先使用系统文档架构管理打开、自动保存、撤销和关闭时的未保存处理。选区、搜索和临时拖拽预览属于每个窗口的会话状态，不通过普通视口变化触发文档写入。一个文档的撤销记录、焦点和选区不得串到另一个文档。

每窗口的 `EditorSession` 通过弱引用 `TitleEditing` 桥接提交自己的画布标题草稿。命令、选区变更、复制粘贴和保存/导出先提交标题；提交失败就保留输入并中止后续操作。画布暂时摘下编辑引用后执行同一套 rename 事务，避免递归提交；成功才移除输入框。`beginEditing` 返回是否已经开始，SwiftUI 仅在成功时消费请求，防止旧输入框尚在时吞掉新主题的编辑请求。协议只管理提交时序，文档仍只有 FileDocument binding 一份来源，撤销仍由命令与 UndoManager 管理。

新格式不假装兼容旧 `.wmind`。首版迁移通道是从旧版导出 Markdown，再在新版导入；仅迁移主题层级与可表达文本，旧样式及附属结构不承诺保留。若用户需要旧文件直接打开，须在开始实现前扩大迁移范围，不能通过忽略字段的方式静默丢失数据。

Markdown 与原生格式共享 `DocumentCodec.maxTopics/maxDepth`。解析时允许暂存容器占用一个额外树层级，主题计数只包含实际读入的节点；决定是否提升唯一根节点后再按最终树完整校验。这样恰好 10000 主题、深度 128 的导出可重导入，保留容器的森林和超限深树仍会拒绝。Tab 只参与前导缩进的宽度计算，标题、引用备注与代码内容保持原始字符。

### 布局和导出

布局输出节点矩形、文本测量结果和连线路径，画布与 PNG/PDF 导出复用同一份几何。折叠后代不参与可见布局或图片导出；Markdown 导出保留完整树。根分支分侧保持稳定，避免编辑某个标题导致所有分支换边。导出不包含选择框、控制柄和编辑输入框。

`PlacedTopic.hasHiddenChildren` 在布局时记录是否有折叠后代，`foldBadgeFrame` 直接从最终节点矩形计算；画布绘制和命中共用它，命中仅额外扩大 1 点。点击时扫描几何元数据，不再对每个可见主题重新递归查树，所以一次空白点击是线性扫描；平移工作区后也不用重建按钮坐标。空叶即使带 collapsed 标记也没有可展开按钮。

### 仓库和环境边界

原生工程替换旧版 Web 源码、部署、CI 和开发说明。旧版 Git 历史、许可证和原始截图保留；旧版未跟踪和忽略的 .env、数据库、上传、依赖缓存不删除。每个窗口持有独立 EditorSession 与系统 UndoManager，FileDocument binding 是唯一文档源。

原生工程的运行入口是 `script/build_and_run.sh`，Codex Run 按钮指向同一脚本。macOS 使用系统 Swift 6 工具链，Linux 安装签名验证过的 Swift 6.1.3，只运行内核；不再启动 Go/Vite 服务。发布签名和公证不属于本次本地开发构建，开发 .app 使用 ad-hoc 签名。

按原生技术、文档、布局、内核和导入导出检索了 proposed、implemented 和 rejected。尚无原生 Swift/macOS 方案，本次是架构方向变更，不能原地改写 Web 架构的决定。

- [编辑器内核](../../implemented/architecture/2026-10-18-wmind-editor-kernel-model.md)、[文本测量与布局](../../implemented/architecture/2026-10-18-wmind-editor-measure-layout.md)、[布局结构](../../implemented/architecture/2026-10-18-wmind-layout-structures.md)：部分重叠，保留命令、空操作、独立编辑会话、稳定布局和共享几何等理由；Swift 的实现不沿用 TS 状态库。
- [服务端持久化](../../archived/architecture/2026-10-18-wmind-map-persistence.md)：服务端鉴权、乐观锁与数据库部分在原生实现落地后退出；文件原子保存、格式错误处理改由本地文档体系承担。
- [Markdown/OPML 导入](../../implemented/architecture/2026-10-20-wmind-markdown-opml-import.md)和[混合标题保留修复](../../implemented/bug-fix/2026-10-25-wmind-markdown-heading-preservation.md)：Markdown 部分重叠；保留标题/列表层级、代码围栏和转义处理的回归理由；OPML 不纳入首版。
- 网站后台、安全、分享、部署和附件相关笔记归属旧产品，其实现已经退出当前工程；被完全取代的笔记保留为带哈希封印的历史归档，仍有跨平台参考价值的内核/布局/Markdown 笔记保留并注明适用边界，旧提案转为 rejected。

## Alternatives considered

**保留 Web 编辑器，用 WKWebView 包装原生窗口。** 最强理由是能沿用已经通过 1433 项前端单元测试的编辑器，缩短第一版交付时间。但它仍保留 JS、Web 渲染与两套交互边界，不满足用户明确要求的 Swift 全面重构，因此不采用。

**全部画布和输入都使用 SwiftUI。** 最强理由是 UI 技术统一、样板少，声明式状态更直观。这里仍需要准确的文本编辑、坐标转换、命中与拖拽，采用小范围 AppKit 画布可以集中处理这些事件，同时保留 SwiftUI 外壳。

**保留 SQLite 作为原生文档库。** 最强理由是支持集中检索和大量文档列表，也能承接旧库的一部分结构。当前范围是本地文件编辑，系统文档架构已经覆盖保存、最近使用与多窗口；额外数据库增加迁移和备份边界，因此首版不采用。

**保留 pretty-print，并在打开时拒绝会膨胀的文档。** 能保持人工阅读方便，也避免打开后不能保存，但会拒绝本来远低于 8 MiB 的合法深树。紧凑编码保留 version 1 和全部字段，同时让大小限制约束实际内容；人工检查可临时格式化副本。

**直接提高 Markdown 的统一上限。** 能放过临界样例，但会让多根文档实际超过内核上限，且仍不能解释何时删除暂存容器。只为容器提供有限的解析余量，并校验最终树，可以同时保留边界兼容与资源约束。

**只在新增按钮中结束全局 first responder。** 改动最小，但菜单、复制和后续结构命令容易遗漏，还依赖哪个窗口当前为 key window。按窗口弱引用标题编辑器使所有事务入口共享提交约束，也能用没有全局窗口的原生会话测试检查交接；代价是维护一个小型生命周期协议。

**单独为画布维护 UUID 到主题的字典。** 可将反复查树变为常数查询，但额外索引必须随每次文档替换同步，绘制和命中仍容易各自定义按钮。布局已有可见节点与左右方向，存一个折叠后代标记足以完成共享几何和线性命中；只有实测线性扫描也不足时再考虑空间索引。

## Verification scope

- Mac 上通过 Xcode 构建并启动应用；离线可用，无需 Go、Node、Docker、账号或网络服务。
- 连续新建子/同级主题、改名、删除、复制、拖动、折叠后，撤销/重做与保存重开保持树结构、顺序、备注、颜色一致。
- 根节点不可删除；非法循环拖拽无效且不写历史；输入框内的删除不触发主题删除；中文输入法和多行标题正常。
- 多文档同时编辑、关闭和重新打开，无历史/选区串扰；未保存内容依系统机制保存或明确询问，不静默丢弃。
- Markdown 混合标题/列表、代码围栏与转义样例导入层级正确；导出重导入保留受支持的主题内容。
- 含中文、长标题、折叠和左右分支的样例导出 PNG/PDF，无裁切和遗漏；1000 节点场景检查重叠、布局时间与滚动体验，性能数据仅报告实测结果。
- 内核测试覆盖序列化、版本错误、命令、历史、树约束、布局和 Markdown；macOS CI 构建应用并执行相关测试。Mac 未实测的界面和打包项目明确列为未验证。
- 旧 Web/部署入口退出当前构建和说明，用户本地数据与许可证保留，必要的历史决定说明可追溯。

## Consequences

- 当前 Linux 云环境不能运行 AppKit/SwiftUI，也没有 Xcode。可继续编写原生工程和准备自动验证，但完整交付验收需要 Mac 或可用的 macOS CI；不能据此承诺已运行的 `.app`。
- Swift 全面重写会放弃旧版大量功能和测试代码；只迁移仍属于核心范围的不变量，不能把旧测试通过数当作新实现的证明。
- Markdown 迁移无法保留全部旧数据。默认不直接写回 `.wmind`、不修改旧数据库；直接兼容旧格式需要单独实现与回归。
- 单文件树模型和简单布局的成本更低，但大文档和中文文本测量仍须实测。若 1000 节点场景不满足交互验收，优先定位绘制/命中热点后再考虑空间索引或分块渲染。

### 当前验证结果

`DocumentTests.compactDeepDocumentRemainsSaveableAndEditable` 先复现打开成功但保存抛出 `tooLarge`，修复后验证保存、重开和改名；旧带缩进文档的回归仍保留完整内容。相关 7 项文档测试在 Linux 执行；不替代 macOS 系统文档验证。

Markdown 的新增用例先复现节点上限拒绝和标题/备注 Tab 变空格；相关 8 项测试在 Linux 验证临界节点数、深度、保留容器的超限拒绝及 Tab 列表缩进。Markdown 不保存颜色、UUID 或折叠状态的既有边界不变。

`EditorSessionTests` 补充标题草稿后新增子/同级主题、撤销重做、窗口隔离和提交拒绝的 4 项用例；当前 Linux 只完成这些 App/原生测试文件的 Swift 语法解析，未执行 AppKit 类型检查或原生测试。真实快捷键、中文输入法和系统保存仍需 Mac 验收。

6 项布局测试在 Linux 验证左右折叠按钮、隐藏后代、空叶、展开后的状态、工作区坐标平移和 10000 个可见主题的空命中。独立 `swiftc -O` 基准比较相同 10000 主题的旧查树循环与新几何扫描；它不包含 AppKit 事件处理，不能当作 Mac 点击延迟。

Swift 6.1.3 Linux 工具链通过 Swift 官方仓库公钥及发布签名验证。`swift build` 和 24 项内核测试通过，覆盖文件往返、格式/资源限制、命令事务、无效移动、空操作、Markdown 和两种布局各 1001 个节点的不重叠检查。App 源码通过 Swift 语法解析，构建脚本通过 Bash 语法检查，并在 Linux 明确拒绝运行 GUI。

macOS 应用目标、4 项原生会话/撤销/测量测试、系统保存、界面交互、图片/PDF 实际观感及 .app 启动在本机未执行；macOS CI 与人工验收文档提供执行入口，不能据此视为已通过。SwiftUI/AppKit 桥接和系统文档行为仍是主要验证风险。

旧 Web 构建与 982 个跟踪文件退出当前入口，旧本地忽略文件保留。120 篇被取代的 implemented 笔记通过原归档工具冻结并记录哈希，11 篇旧提案转为 rejected；当前 18 篇活跃笔记及全部封印通过校验。云环境 install_script/start_skill 草稿已改为 Swift 工作流，并移除仅为旧 Go 模块下载申请的自定义 storage.googleapis.com 域名；保存不代表已发布或已在新任务恢复。
